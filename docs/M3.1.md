# M3.1 – Save-Sheet lesen (0.2.1)

Stand: 18.10.2026. Ausgangsbasis: PR #2, `feat/m3-safe-youtube-actions`, `cea9ec4`. Der Nutzer bestätigte für 0.2.0 das Öffnen des richtigen Video-Tabs und des Save-Dialogs; die alte Erkennung lief anschließend in einen Timeout. Der frühere Fokusfehler folgte einem manuellen Tabwechsel und ist kein bestätigter Adapterfehler. Kein eigener angemeldeter YouTube-Live-Test und keine echten Schreibtests in diesem Änderungsschritt.

## Erkannte Struktur und Rückgabe

Zusätzlich zum unveränderten Legacy-Grundvertrag werden sichtbare `yt-sheet-view-model` berücksichtigt. Erwartet werden `tp-yt-iron-dropdown` innerhalb von `ytd-popup-container` als Vorfahren sowie genau ein `yt-contextual-sheet-layout` und ein darin liegender `yt-panel-header-view-model h2` mit Save-Titel. Unterstützte Titel: `Save to`, `Speichern in`, `Speichern unter`, `In Playlist speichern`, `Speichern`, jeweils auch mit `…`/`...`. Das sind synthetisch getestete Sprachvarianten, keine Bestätigung sämtlicher Live-Übersetzungen.

Genau ein sichtbarer unterstützter Dialog ist erlaubt; mehrere sichtbare Sheets, gemischte Legacy-/Sheet-Wurzeln oder ein fremder Dialog führen zum Abbruch. Versteckte/inert/ARIA-versteckte Vorfahren werden berücksichtigt. Die angeforderte Video-ID muss weiterhin exakt zur Watch-URL und zum einzigen sichtbaren `ytd-watch-flexy[video-id]` passen; der Save-Button muss darin liegen. Fokus und Sichtbarkeit werden erneut geprüft. Keine dynamischen CSS-Klassen im neuen Vertrag.

Nur `toggleable-list-item-view-model` innerhalb dieses Sheets werden gelesen. Jede Zeile benötigt genau ein sichtbares `yt-list-item-view-model` mit genau einem sichtbaren `button[role="menuitem"]`. Zusätzliche Buttons außerhalb dieser Zeilen, insbesondere „New playlist“, werden ignoriert. Die Anzahl 16 ist eine Fixture, keine fest codierte Begrenzung oder Vollständigkeitsgarantie. Ausgelesen werden nur aktuell im DOM sichtbare Einträge, keine unsichtbaren/virtualisierten Listenbestände.

`getAvailablePlaylists` liefert je Zeile:

- `title`: zugänglicher Name über `aria-label`, eindeutig zeileninternes `aria-labelledby` oder Text. Zusätzlicher Buttontext kann Teil des ausgelesenen Namens sein; er ist kein Identitätsbeweis.
- `checked`: ausschließlich exaktes `aria-pressed="true"`/`"false"` im Sheet; fehlende/ungültige oder widersprechende ARIA-/Input-Zustände werden `null`. Legacy nutzt weiter Checkboxzustände.
- `id`: ID aus einem sichtbaren, eindeutigen expliziten YouTube-Playlist-Link **derselben Zeile**, sonst `null`. Bestätigter Nutzerdialog: **keine Links, daher keine belegten IDs**.
- `identity`: `explicit-link` oder `unverified`; `variant`: `sheet` oder `legacy`; `diagnostic` bei fehlender Identität oder unbekanntem Zustand.
- `writable`: für Sheets immer `false`, auch wenn ein künftiges Sheet einen expliziten Link enthält. Keine neue Schreibfähigkeit wird behauptet.

LaterSift zeigt alle gelesenen Einträge einschließlich gleicher Namen, unbekannter Zustände und WL an. Nur schreibbare Legacy-PL-Ziele erscheinen im Ziel-Picker. Enthält ein Legacy-Dialog eine nicht identifizierbare Zeile, bleiben alle zurückgegebenen Schreibziele gesperrt; die bisherige vollständige ID-Prüfung des Archiv-Preflights wird durch die Diagnose-Rückgabe nicht gelockert. Fehlende IDs werden weder durch Titel noch durch Index, Bild, manuelle URL oder vermeintliche WL-Labels ersetzt. Die Rückgabe ist eine flüchtige Diagnose, kein Mitgliedschaftssnapshot und keine Freigabe.

Die erfolgreiche Sheet-Discovery lässt den Dialog im Arbeitstab geöffnet; nach der abgeschlossenen Abfrage kann der Nutzer zu LaterSift wechseln. Sie klickt nur den geprüften Save-Button, keine Playlist-, New-playlist- oder geratenen Schließen-Schaltflächen. Legacy-Discovery schließt wie bisher. Ein bereits vor dem Auftrag offener Dialog wird weiterhin abgelehnt; jeder Discovery-Klick öffnet über die bestehende Bridge einen eigenen Arbeitstab.

## Prüfung der Identitätsmöglichkeiten

Diese Bewertung beruht auf dem gemeldeten DOM und dem Repository-Vertrag, nicht auf Zugriff auf eine angemeldete Live-Sitzung.

| Möglichkeit                                                                     | Was sie belegt                                                                                            | Entscheidung für M3.1                                                                                                                                              |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Explizite `/playlist?list=…`-URL in derselben Zeile                             | Direkte öffentliche Beziehung von Zeile und ID                                                            | Legacy-Vertrag bleibt bestehen; in Sheets als `explicit-link` lesbar, allein noch kein Schreib-/Persistenznachweis                                                 |
| Öffentliche ID-/`data-*`-Attribute                                              | Möglicher Kandidat, Bedeutung/Beziehung im gemeldeten DOM nicht bestätigt                                 | Nicht automatisch als Identität akzeptieren; mit rein lesender Diagnose gezielt untersuchen                                                                        |
| Playlist-Links in Navigation/Bibliothek oder reguläre `/playlist?list=ID`-Seite | Identität der dort geöffneten Playlist                                                                    | Keine eindeutige Verbindung zur linklosen Dialogzeile; gleiche Namen bleiben möglich                                                                               |
| Bekannte ID und unabhängiger Scan der regulären Playlist-Seite                  | Bei exakt geprüftem Seitenkontext: Video dort sichtbar; Abwesenheit nur nach belastbar vollständigem Scan | Kein implementierter allgemeiner Zielplaylist-Scan. Bestehender Scanner ist auf WL begrenzt. Löst allein außerdem nicht die Zeilenbindung vor dem Klick            |
| Manuelle Ziel-/Zeilenauswahl mit anschließender Prüfung                         | Nutzerabsicht                                                                                             | Ohne unabhängigen Vorabnachweis der Zeilen-ID kann bereits die erste Mutation falsch sein. Nachprüfung verhindert diesen ersten Fehlklick nicht; daher kein Bypass |
| Name, Reihenfolge, Thumbnail, `aria-pressed` oder Label „Watch later“           | Anzeige bzw. aktueller UI-Zustand                                                                         | Kein eindeutiger Identitäts- oder Persistenznachweis; `unverified`/`unknown`                                                                                       |

**Für den gemeldeten linklosen Sheet-Dialog existiert derzeit keine implementierte unabhängige Verifikation echter Playlist-IDs.** Deshalb sind Add, WL-Remove und Archivieren dort gesperrt. Auch `getPlaylistMembership` liefert für Sheets stets `unknown`, niemals aus `aria-pressed` abgeleitetes `present`/`absent`. Eine unabhängige reguläre Playlist-Seitenprüfung wäre ein eigener Folgeauftrag mit verifizierter Seitenidentität, Vollständigkeit und bewiesener Bindung an die zu klickende Zeile. Keine internen APIs, privaten Seitenobjekte, Cookies oder Tokens.

## Schreibsicherheit und Tests

Der bisherige Legacy-Pfad bleibt experimentell: explizite Zeilen-ID einschließlich WL, exakter Video-Kontext, dauerhaft beanspruchte ausdrückliche Freigabe, Snapshot/Export, Journal vor Klick, einmaliges Background-Permit und Pilotlimit 1. Jede Mitgliedschaftsbeobachtung über die Bridge erzwingt weiterhin einen frischen Hard-Reload mit Cache-Bypass; Checkboxfeedback bleibt kein Erfolg. Die synthetischen vollständigen Schreibtests prüfen diesen Vertrag einschließlich optimistischer Fehlrückmeldung weiter. **Keine nachweislich live unterstützte neue Schreiboperation.**

Neue synthetische Fixtures prüfen 16 Zeilen, beide ARIA-Zustände, New playlist, gleiche Namen, fehlende IDs, unbekannte/widersprüchliche Zustände, unzulässige Links, mehrere/versteckte Sheets, Sprachvarianten, Fokusverlust, Dialogschluss, falschen Video-Kontext und Legacy-Kompatibilität. Vollständige Integrationen mit echtem Storage, Executor, Autorität, Bridge, Content und DOM-Adapter prüfen die Rückgabe der Discovery sowie das Blockieren freigegebener Add-/Remove-Abläufe vor jedem Permit/Playlist-Klick. Die UI-Prüfung verwendet ausdrücklich einen Transport-Fixture und ist kein YouTube-Live-Nachweis.

Prüfergebnisse und Artefakt: [STATUS.md](STATUS.md). Bestehende Qualitätsprüfungen: [TESTING.md](TESTING.md).

## Manueller Zen-Test – ausschließlich lesend

1. Vollständiges JSON lokal sichern. 0.2.1 mit derselben Erweiterungs-ID im vorhandenen Profil laden; keine Neuinstallation mit Datenlöschung. Version prüfen.
2. Archivziel-Dialog → **Playlists aus YouTube laden**. Den ausdrücklich geöffneten YouTube-Arbeitstab bis zum Abschluss aktiv/fokussiert lassen. Keine Playlist und kein New playlist anklicken.
3. Prüfen, ob Save-Sheet erkannt wird und geöffnet bleibt. Nach Abschluss zu LaterSift wechseln. Erwartet bei der gemeldeten Struktur: 16 Namen, wahre/falsche UI-Auswahl, überall „Identität unbestätigt“, kein schreibbares Ziel aus diesem Sheet. Mit dem nativen Dialog visuell vergleichen; keine feste Vollständigkeitsbehauptung bei abweichender Zeilenzahl.
4. Gleiche Playlist-Namen müssen getrennt erscheinen; eine eigene Playlist namens „Watch later“ darf nie als WL-Schreibziel aufgelöst werden. Wenn verfügbar, deutsche und englische Oberfläche vergleichen.
5. Separat Fokus während einer laufenden Abfrage wechseln oder Dialog schließen: verständlicher Abbruch, keine Playliständerung. Ein Fokusabbruch bei manuellem Wechsel ist erwarteter Schutz.
6. **Keine Ausführung von Entfernen, Archivieren oder Bereinigung** für diese Abnahme. Es liegt keine gesonderte Freigabe für echte Schreibtests vor.

Falls die Erkennung fehlschlägt, Save-Dialog manuell geöffnet lassen und folgendes ausschließlich lesende Snippet in der YouTube-Konsole ausführen. Es liest nur DOM/Styles, klickt nicht, sendet keine Requests und liest keine privaten Properties. Es gibt weder Playlist-Namen noch Playlist-IDs aus; Strukturbericht vor dem Teilen prüfen. Damit lässt sich insbesondere die noch nicht live bestätigte Beziehung zwischen Zeile, Listenelement und Menübutton abgleichen.

```js
(() => {
  const visible = (el) => {
    if (!el.isConnected) return false;
    for (let n = el; n; n = n.parentElement) {
      const s = getComputedStyle(n);
      if (
        n.matches('[hidden], [inert], [aria-hidden="true"]') ||
        s.display === 'none' ||
        s.visibility === 'hidden' ||
        s.visibility === 'collapse' ||
        s.opacity === '0'
      )
        return false;
    }
    return true;
  };
  return [...document.querySelectorAll('yt-sheet-view-model')].map((sheet) => ({
    visible: visible(sheet),
    dropdown: !!sheet.closest('tp-yt-iron-dropdown'),
    popup: !!sheet
      .closest('tp-yt-iron-dropdown')
      ?.closest('ytd-popup-container'),
    layouts: sheet.querySelectorAll('yt-contextual-sheet-layout').length,
    headings: sheet.querySelectorAll('yt-panel-header-view-model h2').length,
    rows: [...sheet.querySelectorAll('toggleable-list-item-view-model')].map(
      (row, index) => ({
        index,
        visible: visible(row),
        items: row.querySelectorAll('yt-list-item-view-model').length,
        links: row.querySelectorAll('a[href*="list="]').length,
        publicIdAttributeNames: [row, ...row.querySelectorAll('*')].flatMap(
          (el) =>
            el.getAttributeNames().filter((a) => /playlist|list-id/i.test(a)),
        ),
        buttons: [...row.querySelectorAll('button')].map((button) => ({
          role: button.getAttribute('role'),
          pressed: button.getAttribute('aria-pressed'),
          checked: button.getAttribute('aria-checked'),
          labelled:
            button.hasAttribute('aria-label') ||
            button.hasAttribute('aria-labelledby'),
          insideItem: !!button.closest('yt-list-item-view-model'),
          chain: (() => {
            const tags = [];
            for (let n = button; n && row.contains(n); n = n.parentElement)
              tags.push(n.localName);
            return tags;
          })(),
        })),
      }),
    ),
  }));
})();
```
